# Metric cards and definitions

These React components display supplied values and explain their meaning. The browser preview at `/e2e/metrics.html` uses synthetic inputs; screen integration and metric computation are separate work.

| Component     | Contract                                                                                                                                                                                                                                                                                                                                                                |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MetricCell`  | `value` accepts a number, string, null, or undefined. Finite numbers use optional `format` (default `String`); nonempty strings remain verbatim. Missing, blank, NaN, and infinite values render `Unmeasured`. Sizes: 10.5, 11 (default), 18, 24, 30 px. `align="right"` fills the allocated cell and aligns its contents right.                                        |
| `Unmeasured`  | Visible em dash, screen-reader text `Unmeasured: <reason>`, and a native title. Default reason: `This value was not measured`. Supply a specific reason when known. A measured zero remains zero.                                                                                                                                                                       |
| `StatTile`    | Required `label`, `ruleId`, and `icon`; optional `value`, `format`, `reason`, `unit`, `delta`, `deltaTone`, `aside`, `tip`, and `iconTone`. A 52 px card fills its container. Icon and label sit left; value, unit, delta, and aside sit right. The whole tile is a definition button. Long labels and asides truncate visually while preserving their accessible text. |
| `SectionCard` | Required `title` and `children`; optional `ruleId`, `meta`, `right`, and `footer`. Header height defaults to 40 px, with a 36 px variant. Panel padding defaults to `12px 14px 10px`; `padding` accepts a CSS value. Each section has a unique accessible heading association. The caller owns slot contents and actions.                                               |
| `RuleChip`    | Required typed `ruleId`; `size` is `normal` (default) or `sm`. A button named `Definition <id>` exposes the definition through `aria-describedby`. Do not nest inside another button.                                                                                                                                                                                   |
| `RulePopover` | Required `ruleId` and a single native button element as `children`; optional `context` adds a caller-supplied explanation. Composes Base UI Tooltip for hover, focus, Escape, and positioning.                                                                                                                                                                          |

```tsx
<StatTile
  label="Tokens"
  ruleId="M-04"
  icon="token"
  value={null}
  reason="Cursor Agent CLI usage is absent; token totals were not measured."
/>
```

`StatTile` shows a finite supplied delta only when its main value is measured. Positive changes use ▲, negative changes use ▼, and zero uses `0%`. `deltaTone="good"` uses success color; `bad` uses warning color. Direction does not choose the tone. The caller owns sample eligibility, unit conversion, and metric interpretation.

The shared `Icon` module supplies the reviewed artwork: `lanes` (info), `merge` (accent), `clock` (success), `bolt` (danger), `msg` (warning), `token` (info), and `shield` (success). `MetricIcon` adds the 28 px icon box and default tone. `iconTone` can override it with info, accent, success, danger, warning, or meta. Icons are decorative; the adjacent label supplies their meaning.

## Formatting

Formatters use `en-US`, accept numeric inputs only, and return an em dash for null, undefined, NaN, or infinity. Negative zero is normalized. Finite negative inputs retain their sign; domain validation belongs to the producer.

| Helper             | Input                                                                                                    | Example                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `tokens`           | Token count; plain below 1,000, K from 1,000, M from 100,000, B from 1,000,000,000; at most two decimals | 15,100,000 → `15.1M`; 400,000 → `0.4M`; 3,720,000,000 → `3.72B` |
| `count`            | Count, rounded to an integer with grouping                                                               | 4,639 → `4,639`                                                 |
| `hours`, `minutes` | Already-converted duration, at most one decimal; no conversion or suffix                                 | 62.3 → `62.3`                                                   |
| `percent`          | Fraction, at most one decimal                                                                            | 0.18 → `18%`                                                    |
| `delta`            | Signed fractional change                                                                                 | 0.18 → `▲18%`; -0.09 → `▼9%`; 0 → `0%`                          |

### One way to write each kind of value

Each kind of value below is written by one function, and every screen that shows
it calls that function, so the same value reads the same everywhere. `—` (em
dash) always means unknown or not measured; a measured zero is shown as a zero
(`0h00m`, `0 h`, `$0.00`), never as a dash.

| Value                      | Function                                                                                 | Example                                                                                                                                                                                                                                       |
| -------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Date and clock time        | `clock`, `calendarDay`, `dayRange` (`kit/clock`)                                         | This Mac's locale and its 12- or 24-hour setting, never a forced locale or hour cycle: `Oct 5, 2:30 PM` or `5 Oct, 14:30`. A report's own time zone is kept.                                                                                  |
| Agent time                 | `agentDuration` / `agentTime` (`app/agent-duration`)                                     | 11,568,000 ms → `3h12.8m`; read aloud as `3 hours 12.8 minutes`; not a duration (NaN, negative) reads `—`. Used by Sessions, a session's page and a stretch's active time, PR sessions, the Dashboard's effort chart and lanes, and the tray. |
| Money                      | `usd` (`kit/format`)                                                                     | Cents below $100, whole dollars from $100: `$12.40`, `$250`, `$1,235`; `<$0.01` for a positive amount under a cent.                                                                                                                           |
| Host name                  | `hostName` (`kit/hosts`)                                                                 | `Claude Code`, `Codex`, `Cursor`. The account-usage widget says `Claude` on purpose: it shows the Claude account's limits.                                                                                                                    |
| Host and surface           | `surfaceLabel` (`kit/hosts`)                                                             | `Claude Code · cli`; a surface with no label is `Codex · unknown surface`.                                                                                                                                                                    |
| Pull request check status  | `refreshStateLabel` / `refreshStatusWords` / `refreshStatusText` (`dashboard/pr-effort`) | `not checked yet`, `checked`, `could not be checked (timed out)`, `stale after a failed check (rate limited)`; the Merged PRs tile counts with the same words (`3 not checked yet`).                                                          |
| Hands-off time             | `handsOffTime` / `handsOffSpoken` (`app/metric-format`)                                  | Its own quantity, in minutes: a stretch's length, a session's or PR's median, the Dashboard's median, p90 and daily line all read `3.2 min` (aloud `3.2 minutes`).                                                                            |
| Pull request link evidence | `evidenceWords` (`pr-analytics`)                                                         | `exact`, `commit`, `inferred`; the stored `sha` is never shown.                                                                                                                                                                               |
| Token+model coverage gate  | `gatePercentText`, `gateVerdict` (`pr-analytics`)                                        | Rust decides pass or fail. The percent is rounded down to one decimal, so 8,999 of 10,000 reads `89.9%`, never a passing-looking `90%`.                                                                                                       |

## Definitions and accessibility

[The reviewed definition catalog](../design/rule-contract.json) contains 30 technical definitions. `rules.ts` imports it directly and exposes typed IDs. These definitions specify product behavior; displaying them does not implement or verify the metric, privacy, or capture behavior they describe.

M-08 is Leverage: agent hours divided by human time (the time between messages you sent agents at most the break length apart), both over the same whole local days. It replaced the earlier ratio of agent time to estimated typing time (M-07) on 2026-10-05; M-07 itself is unchanged.

M-21 is Session warnings: simple rules, with no model and no score, that say a session probably went wrong somewhere. A warning fires when one rule matches, and each carries its kind, session, time, the saved records it points at and a short reason such as `same prompt sent twice (10:05, 10:12)`. One function, `session_warnings::decide` in `xt-metrics`, decides them; it is not yet in the definition catalog above. The five rules; sidechain records (an agent's own sub-conversation) are left out of all of them:

- **Correction**: a message M-02 calls a person's, sent after an agent reply, contains `wrong`, `stop`, `again` or `I said`; or starts with `no` and has at most 8 words; or has `still` with `not`, `broken`, `fails`, `error`, `same`, `wrong`, `doesn't`, `happening` or `see` within five words. `still not working` and `No, use the other file` match; `I still need an export button` and `there is no test for it yet` do not.
- **Interruption**: an input the store flagged as `[Request interrupted by user…]` (`records.is_interrupted`); an input with a stored proof that Codex wrote its `<turn_aborted>` note (`tool_sent_inputs`, kind `codex_turn_aborted`); or a tool call whose saved result says the person declined it or interrupted it. A stopped call followed by Claude Code's marker, with no agent record between, is one interruption, and so is a marker and a stopped call at the same moment in either order. Records at the same moment are read in their source order: a record after the one it names as its parent, else by saved message ID.
- **Repeated prompt**: the same person's message, lowercased with whitespace collapsed, sent two or more times. Messages of fewer than 4 words are not compared.
- **Repeated failure**: two or more calls with the same stored M-20 comparison key whose saved result says they failed.
- **Admitted mistake**: the agent's reply to a person's message (M-02, not tool-written) admits a mistake. The reply is the first agent record after the message with text (a stored `text_len` above 0); records with only thinking, tool calls or tool results are passed over, later replies are not checked, and a new person's message before any reply text restarts the wait. The reply warns when its first 600 characters hold one of these phrases as whole words, matched without case and with curly apostrophes made straight: `you're right` / `you are right`, `my mistake`, `my bad`, `I was wrong`, `that was wrong`, `I got that/this/it wrong`, `I misread`, `I misunderstood`, `I overstated`, `I overclaimed`, `I should have`, `good catch`, `you caught`, `I explained (that/it/this) badly`, `that's on me`, `I made a mistake`, `I was mistaken`, `sorry`, a word starting `apolog`, `I missed`, `I didn't answer`, `my error`, `fair point`, `I was too`, `I conflated`, `I mixed up`. `wrongly` and `incorrectly` never match. The warning points at the reply and names the person's message and the reply; its reason quotes the first phrase found, `the agent replied "you're right" after your message (14:05)`. A correction and an admission on the same exchange are both shown.

There is no repeated-calls rule. It used to flag the M-09 stretches that M-20 calls circling; on 2026-10-27 it was removed after a review of 200 real warnings found all 127 repeated-calls warnings were false alarms (deliberate polling of a running log, CI run, background job or helper agent; different calls through one tool; different edits to one file). M-20 itself, and the Dashboard's and session page's repeat numbers, are unchanged. Saved answers from before the removal are recounted (saved-answer rule version 4), and a dismissal stored for a `repeated_calls:…` warning names no warning any answer has, so it is never shown or counted.

**Whole session.** The whole-session API reads a session's warnings over its whole history (`MetricsDb::whole_session_warnings`), not over the selected range, so the same session shows the same warnings on the Dashboard's session rows, the Effort card, the Sessions list and its own page. Each session is read over its own window, from a second before its first timed record to two seconds after its last. A session's records that state no time are read by no rule, and every check then says it could not read everything. The Effort card's "human + agent" view reads the warnings inside its report's whole days (`warnings_in_window`): every session with a timed record there, each read over its whole history, keeping only the warnings that fall inside. Only the sessions a screen shows are read: the rows in view of the Dashboard's session table and the Sessions list, one session's page, and the sessions of the Effort card's days while that view is shown. Answers are cached by the UI per session and zone, and read again whenever committed indexing, a sub-session pass or a content purge refreshes session data.

**Reply facts.** No reply text is stored. When a session is indexed, the store reads each agent reply's text blocks in memory and saves only the fixed names of the phrases found, in order of first appearance (migration 30, `reply_admissions`, written next to the tool-result facts for Claude, Codex and Cursor alike). Which names warn is decided when warnings are computed, so narrowing the list needs no rescan; adding a phrase needs a new fact version and one more Claude re-read. A reply with no saved row (indexed before migration 30, or its content never seen), one whose row two observations disagreed on, or one a later build wrote, is unknown: the check then says how many replies could not be checked. Migration 30 clears the Claude transcript checkpoints once, so the next scan reads every Claude transcript again and fills older replies; that same re-read also saves tool outcomes for older Claude results that had none, so older sessions can gain interruption or repeated-failure warnings. Codex and Cursor are read whole on every scan. Saved answers from before this rule are recounted (saved-answer rule version 5).

**Identity.** Each warning has an identity that stays the same while its session grows: `kind:anchor` (`SessionWarning::id`), where the anchor is the saved record the warning starts at: the message (a correction), the marker record (an interruption that began with Claude Code's marker), the stopped call's result record and that result's block in it as `record#block` (an interruption from a declined or interrupted call), the first of the repeated messages (a repeated prompt), the first failed result's `record#block` (a repeated failure) or the agent's reply (an admitted mistake). No two warnings of one session share an identity.

M-20's key (`xt-store` `repeat_key`) identifies a call by its tool name and the first of `command`, `file_path` or `pattern` it states (key version 1). Codex's own command tools state their command elsewhere, so each has its one field instead (key version 2): `exec` its text (`input` as the pinned reader writes it), `exec_command` its `cmd`, `js` its `code`. Under version 1 every call of those tools was the same call, which made long Codex sessions look like circling on the Dashboard. Version-1 keys of every other tool are byte-for-byte unchanged, and this build compares keys of both versions; keys of different versions are never the same call. A Codex call indexed under version 1 keeps its old key until its session file is read again: the next scan replaces it without marking a disagreement (a reading by an older build changes nothing, and a disagreement already marked stays). A session whose source file is gone keeps its version-1 keys and its old answer.

Repeated failure uses M-20's key, so it agrees with M-20 on what "the same call" is. For a tool whose calls name no command, path or pattern (`WebFetch`, `WebSearch`, a browser `navigate`) the key identifies only the tool, so every call of it is the same call; the reason then names the tool, `WebFetch failed twice`, rather than `the same WebFetch call`.

A person's message that opens with a tag (`<ci-monitor-event …>`, `<task-notification>`, any `<word`) is text a tool wrote (`tool_written`), decided once per message: neither text rule reads it, it does not end the agent's reply, so a person's message after it still counts as sent after that reply, and the admitted-mistake rule does not treat it as a message the agent replies to.

Tool results are saved when a session is indexed (migration 27, `tool_results`) as source facts only, with no result text: which call the result answers, its `is_error` flag (true, false, or absent), and which of three fixed kinds of message its text is (`declined`: "The user doesn't want to proceed with this tool use"; `interrupted`: "[Request interrupted by user for tool use]"; `permission_denied`: "Permission for this action was denied", or "Permission to use …" stating "has been denied", Claude Code's own permission check from its mode or settings, not the person) or `other`. How the call ended is decided from those facts when the rules run (`tool_result::outcome` in `xt-store`), so a corrected rule changes no saved row. With `is_error` true, `declined` is the person's decline, `interrupted` is the person's interruption and not a failure, `permission_denied` is neither a failure nor the person's decline (both rules ignore it), and anything else is a failure. `is_error` false is a success. An absent flag is a success for Claude, whose API defines it as false; Codex and Cursor results never state it, so their outcome is unknown and the failure rule cannot run for them. A saved row is replaced only when the same result is read again by a build whose fact version is higher; the same version stating other facts marks the row conflicted, which reads as unknown. Records indexed before migration 27 have no saved result until their file is read again.

The text rules read the message's kept content in full when content is kept, else the index's 280-character preview of a person's message. A preview that stopped at 280 characters is never read as the whole message: the correction rule reads the kept part without its last, possibly cut, word and without the `no` rule (the message's length is unknown), and says the message was not fully read when it finds nothing; the repeated-prompt rule does not compare it and says so. Each rule also says whether it read everything it needed; when words, results, a classification or M-20's count were not kept or not known, it lists what was missing instead of reporting no warnings. A failed result whose call is not among the saved calls is listed once, as unmatched; a declined call whose call is unknown is still an interruption, named `a call to a tool`.

The [coverage report](acceptance/metrics/rule-coverage.json) records the approved-source comparison using only IDs and SHA-256 hashes. Ordinary tests check the expected ID set, important amended clauses, and catalog/report parity. The report records a completed comparison; it is not an independent approval mechanism. Definition changes require source review and an updated report.

Hover or keyboard focus opens the exact definition and optional context. The trigger is explicitly tabbable, and the popup has `role="tooltip"` with a matching `aria-describedby` association. Escape dismisses while retaining trigger focus; Tab leaves normally. The popup contains passive text and does not intercept pointer clicks or move keyboard focus. Body portals preserve the nearest `ThemeScope` and escape ancestor clipping.

The longest usage and coverage definitions are tested at 1120×720. The component follows the app's supported desktop size; it does not promise that long definitions fit arbitrarily small windows. Native title tooltips are reserved for unmeasured reasons and truncated asides, avoiding a second full-definition tooltip over the Base UI popup.
